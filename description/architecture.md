# Структура приложения и технологии

## Схема

```
 Телефон (Android, позже iOS)                         Сервер
┌──────────────────────────────────┐            ┌──────────────────────────────┐
│ Экраны (React Native + Expo      │            │ Django 6.1                   │
│ Router): Учёба / Библиотека /    │            │  ├─ сайт (HTML-страницы)      │
│ Профиль                          │            │  └─ API (Django REST         │
│        │                         │            │     Framework) /api/...      │
│        ▼                         │   HTTPS    │            │                 │
│ Логика: алгоритм повторения (TS),│  JSON +    │  алгоритм повторения (Python)│
│ блитц, прогоны тем, добавление   │  токен     │  тот же, сверен по           │
│        │                         │◀──────────▶│  scheduler_vectors.json      │
│        ▼                         │ /api/sync/ │            │                 │
│ SQLite на телефоне (expo-sqlite):│            │            ▼                 │
│ блитц, темы, прогоны, outbox   │            │ SQLite → PostgreSQL          │
│ Токен: expo-secure-store         │            │ (все пользователи)           │
└──────────────────────────────────┘            └──────────────────────────────┘
```

Телефон работает со **своей** базой. Сервер нужен для входа, библиотеки (чужие наборы) и синхронизации.
Подробности о синхронизации: `algorithm-and-sync.md`.

## Технологии

### Сервер (уже есть)
| Что | Зачем |
|---|---|
| Python, Django 6.1 | сайт, модели, админка |
| Django REST Framework | JSON API для телефона, вход по токену |
| SQLite → PostgreSQL | база. SQLite для разработки, PostgreSQL на боевом сервере |
| gunicorn + nginx + HTTPS (позже) | боевой сервер, без HTTPS телефон не подключить к интернет-серверу |

### Телефон (новое, папка `mobile/`)
| Что | Зачем |
|---|---|
| Expo SDK 58 + React Native, TypeScript | один код для Android и iOS |
| Expo Router | навигация: три вкладки внизу и экраны внутри них |
| expo-sqlite | локальная база: блитц, темы, прогоны, очередь отправки |
| expo-secure-store | безопасное хранение токена входа |
| expo-network | узнать, что сеть появилась, и запустить синхронизацию |
| expo-crypto (`randomUUID`) | id для карточек и ответов, созданных офлайн |
| react-native-gesture-handler + reanimated | свайп карточки: вправо — верно, влево — неверно; переворот |
| Jest | тесты, в том числе алгоритма по `scheduler_vectors.json` |
| Expo Build (бывш. EAS Build) | сборка `.apk` в облаке без Android Studio; позже iOS через TestFlight |

### Как части взаимодействуют
1. **Вход:** приложение отправляет ник/email и пароль на `/api/auth/token/`, получает токен,
   кладёт его в secure-store. Дальше каждый запрос идёт с этим токеном.
2. **Первая синхронизация:** `/api/sync/` без `since` скачивает весь блитц, темы и прогоны в SQLite.
3. **Учёба офлайн:** экраны читают и пишут только локальную SQLite. Каждый ответ в блитце
   сразу двигает карточку локально (TS-алгоритм) и кладёт событие в `outbox`.
4. **Синхронизация:** когда есть сеть, `outbox` уходит на `/api/sync/`, приходят изменения с сервера,
   локальная база обновляется, `outbox` очищается.
5. **Библиотека:** «Мои темы» и «Добавленные темы» лежат на телефоне и работают без сети
   (добавленные — только для чтения, обновляются при синхронизации). «Смотреть библиотеку» —
   онлайн: поиск по публичным темам, страница темы и автора, добавление темы себе,
   копирование карточек и добавление их в блитц.

## Что уже сделано и что придётся менять

### Сервер — переиспользуем почти всё
- ✅ Алгоритм повторения, модели (карточки, темы, журнал ответов, прогоны, удаления).
- ✅ API: вход, библиотека, копирование тем и отдельных карточек, синхронизация. Покрыто тестами.
- ✅ Прогоны «просто учёбы» уже умеют «продолжить» и «начать заново».
- ⏸ **Регистрация через API** отложена. Пока для тестов есть аккаунт администратора `admin`
  (вход и на сайте, и в приложении).
- ⚠️ **Блитц отдельно от карточек**: карточка может быть в теме, но не в блитце, а в блитц можно
  класть и чужие карточки. Нужна переделка моделей, API и синхронизации — вариант выбирается
  в `open-decisions.md`, п. 1.
- ⚠️ **«Добавить тему себе» = подписка**, а не копирование, как сейчас. Плюс теги, поиск,
  страница автора, массовые действия над карточками.

### Сайт — работает, но в старом дизайне
- Блитц (страница Review), просто учёба, добавление и список карточек уже есть.
- Отличия от описания: после добавления карточки форма не остаётся открытой с той же темой;
  список карточек показывает другие колонки. Это небольшие правки. Редизайн сайта — после приложения.
