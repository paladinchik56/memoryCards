# Как запустить приложение на Android

Есть два способа:

| | Expo Go (для разработки) | Своё приложение `.apk` |
|---|---|---|
| Что это | Бесплатное приложение Expo Go из Google Play, внутри которого запускается наш код | Отдельное приложение «Cards» со своей иконкой |
| Когда нужно | Пока идёт разработка: правки в коде видны на телефоне **сразу**, без переустановки | Чтобы пользоваться как обычным приложением или дать кому-то |
| Нужен компьютер рядом | Да, приложение загружается с компьютера по Wi-Fi | Нет, нужен только сервер |
| Нужен аккаунт Expo | Нет | Да, бесплатный (сборка идёт в облаке Expo) |

В обоих случаях приложению нужен **сервер Django**, доступный с телефона (шаг 1). Проще всего запустить его через Docker.

---

## Шаг 1. Запустить сервер (и Expo) так, чтобы телефон их видел

Телефон и компьютер должны быть **в одной Wi-Fi сети**. Узнайте IP компьютера в локальной сети:
```
hostname -I
```
Нужен первый адрес, например `192.168.0.65`.

### Вариант А. Docker — одной командой (рекомендуется)

Нужны только Docker и Docker Compose: `.venv`, `pip install` и `npm install` на компьютере не нужны.

```
cd /home/paladinchik56/PycharmProjects/DjangoProject
docker compose --profile mobile up   # сервер (сайт + API) на :8000 и Expo на :8081
docker compose up                    # только сервер, если телефон не нужен
```

- При старте сервер печатает, что открывать:
  ```
    Computer: http://localhost:8000/
    Phone:    http://192.168.0.65:8000/
  ```
  Ниже Django пишет `Starting ... at http://0.0.0.0:8000/` — это **не адрес для браузера**, а настройка
  «принимать подключения на всех адресах компьютера». Открытие `0.0.0.0:8000` даёт «Bad Request (400)».
- Логи сервера (каждый запрос и полный текст ошибок): `docker compose logs -f web`.
- Первый запуск дольше (скачивание образов и `npm install` внутри контейнера, несколько минут).
- Когда Expo готов, в логах появится **QR-код** для Expo Go — переходите к Способу 1, шаг 3.
- Если IP не `192.168.0.65`, укажите свой:
  ```
  LAN_IP=192.168.0.70 DJANGO_ALLOWED_HOSTS=localhost,192.168.0.70 docker compose --profile mobile up
  ```
- Порты 8000 и 8081 должны быть свободны. Если сервер или `expo start` уже запущены вручную —
  остановите их или выберите другие порты: `WEB_PORT=8001 EXPO_PORT=8082 docker compose --profile mobile up`
  (тогда и на телефоне адрес сервера `http://<IP>:8001`).
- В фоне: добавьте `-d`; QR-код и логи — `docker compose logs -f mobile`.
- Остановить: `Ctrl+C` (или `docker compose down`, если запускали с `-d`).
- Код и база `db.sqlite3` берутся из папки проекта: правки видны сразу, данные не теряются.
- Команды Django выполняются внутри контейнера:
  ```
  docker compose exec web python manage.py import_topic "my content/тема.json"
  docker compose exec web python manage.py test
  docker compose exec web python manage.py createsuperuser
  ```
- После изменения `requirements.txt` пересоберите образ: `docker compose build`.

### Вариант Б. Вручную, без Docker

```
cd /home/paladinchik56/PycharmProjects/DjangoProject
DJANGO_ALLOWED_HOSTS="192.168.0.65,localhost" .venv/bin/python manage.py runserver 0.0.0.0:8000
```
`0.0.0.0` — принимать подключения не только с этого компьютера. `DJANGO_ALLOWED_HOSTS` — разрешить
обращаться к серверу по этому IP. Этот терминал должен оставаться открытым, пока пользуетесь приложением.
Expo в этом варианте запускается отдельно (Способ 1, шаг 2).

### Проверка

Откройте на телефоне в браузере `http://192.168.0.65:8000` — должна открыться страница сайта.
Если не открывается — см. «Если не работает» внизу.

## Способ 1. Expo Go (разработка)

1. Установите на телефон **Expo Go** из Google Play.
2. Запустите Expo:
   - **с Docker** (вариант А) — уже запущен, QR-код в логах `docker compose --profile mobile up`;
   - **вручную** (вариант Б) — во втором терминале:
     ```
     cd /home/paladinchik56/PycharmProjects/DjangoProject/mobile
     npm install          # только в первый раз и после смены зависимостей
     npx expo start
     ```
3. Откройте Expo Go, нажмите **Scan QR code** и наведите на QR-код.
4. Приложение загрузится. На экране входа адрес сервера уже подставлен (берётся IP компьютера).
   Войдите — например, тестовым аккаунтом `admin` — или продолжите без аккаунта.

**Как работает разработка:** после сохранения файла в `mobile/src/` приложение на телефоне обновляется само
через 1–2 секунды. Переустанавливать ничего не нужно. Если что-то «залипло» — встряхните телефон
(откроется меню разработчика) → **Reload**.

## Способ 2. Своё приложение `.apk` (облачная сборка Expo)

### Один раз
1. Зарегистрируйтесь на https://expo.dev/signup (бесплатно).
2. Войдите из терминала (лучше в отдельном терминале, например в WebStorm — будут вопросы):
   ```
   cd /home/paladinchik56/PycharmProjects/DjangoProject/mobile
   npx eas-cli@latest login
   ```

### Каждая сборка
```
cd /home/paladinchik56/PycharmProjects/DjangoProject/mobile
npx eas-cli@latest build -p android --profile preview
```
- При первой сборке на все вопросы отвечайте **Yes**: создать проект в аккаунте Expo, package
  `com.paladinchik.cards`, создать ключ подписи (keystore — Expo хранит его у себя).
- Сборка идёт на серверах Expo: на бесплатном тарифе 10–30 минут вместе с очередью.
  Прогресс — на https://expo.dev в разделе **Builds**; терминал можно закрыть.
- В конце — ссылка и QR-код. Откройте ссылку на телефоне, скачайте `.apk`, установите. Android
  попросит разрешить установку из этого источника (браузера) — разрешите.
- После первой сборки Expo допишет идентификатор проекта в `mobile/app.json` — это изменение нужно закоммитить.

Новая версия приложения = новая сборка и установка поверх старой (данные сохраняются).

### Адрес сервера в `.apk`
На экране входа по умолчанию стоит `http://192.168.0.65:8000` (задан в `mobile/app.json` → `extra.defaultServer`).
Если у компьютера другой IP — просто исправьте адрес в поле на экране входа.

## Если не работает

| Что видно | Что делать |
|---|---|
| «Сервер недоступен» на экране входа | Проверьте «Проверку» из шага 1 (страница открывается в браузере телефона?). Телефон в той же Wi-Fi, не в мобильном интернете? Сервер запущен с `0.0.0.0:8000` (или через Docker)? |
| «Bad Request (400)» | Открыт адрес `0.0.0.0:8000` — откройте `localhost:8000` (на компьютере) или `http://<IP>:8000` (на телефоне). Иначе IP не указан в `DJANGO_ALLOWED_HOSTS` |
| В браузере телефона страница не грузится вообще | Брандмауэр на компьютере: `sudo ufw allow 8000` (если включён ufw) |
| Expo Go не подключается к QR-коду | Проверьте `LAN_IP` (Docker) или запустите вручную `npx expo start --tunnel` (идёт через интернет, медленнее, но работает в любых сетях) |
| Expo Go пишет о несовместимой версии SDK | Обновите Expo Go в Google Play (проект на Expo SDK 58) |
| После смены IP компьютера ничего не работает | Новый IP — в `DJANGO_ALLOWED_HOSTS` (и `LAN_IP` для Docker) при запуске и в поле адреса на экране входа |
| Docker: `port is already allocated` | Порт занят вручную запущенным сервером или Expo — остановите их или задайте `WEB_PORT` / `EXPO_PORT` |
| Docker: `permission denied ... docker.sock` | Добавьте себя в группу docker: `sudo usermod -aG docker $USER` и перелогиньтесь |

## Нужен ли эмулятор Android?

Для этого компьютера — **не рекомендую**:
- эмулятору нужна Android Studio / Android SDK (8–15 ГБ на диске) и 2–4 ГБ оперативной памяти;
- у компьютера 7,6 ГБ памяти, и при открытых WebStorm и PyCharm свободно около 1,5 ГБ — эмулятор будет
  тормозить и заставит систему уходить в swap;
- главное — переустанавливать приложение на телефон при разработке и так не нужно: в Expo Go правки
  появляются на телефоне сами за 1–2 секунды (см. Способ 1). Реальный телефон к тому же честнее
  показывает свайпы, клавиатуру и скорость.

Эмулятор имеет смысл, если понадобится проверить другие размеры экрана или версии Android,
или если станет больше памяти (16 ГБ и выше).
